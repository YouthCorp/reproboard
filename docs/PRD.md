# 제품 계약

상태: 제품 계약. D10 검색·필터·정렬·상세 URL까지 로컬 구현하고 신규 기능을 동결했다. 멘션/알림은 유지하며 미구현 /demo 신규 화면은 후속으로 옮겼다. GitHub OAuth 코드는 있으나 외부 앱 등록 전 실제 왕복은 NOT_RUN이다. 실제 검증 상태는 PROGRESS를 기준으로 구분한다.

## 목표

소규모 개발팀이 버그 재현 정보를 갖추고 우선순위를 정한 뒤 수정·재검증까지 완료한다. 대상 규모 3~8명, MVP 조회 범위 워크스페이스당 500개 이슈 이하. 성능 검증용 기본 합성 데이터는 100개.

## 필드

- issue id(UUID), 사람이 읽는 issue key, workspace id.
- title: 1~120자. creation에 필수.
- steps / expected / actual / environment: 각각 최대 4,000자. Inbox에는 비어 있을 수 있다.
- reproduction: unknown(기본값) / reproduced / intermittent / not_reproduced. intermittent는 발생 조건 메모 `reproduction_note` 필수. 메모는 최대 4,000자.
- severity: unset / S1 / S2 / S3 / S4. S1 핵심 기능 중단·데이터 손실, S2 주요 기능 문제·우회 어려움, S3 부분 문제·우회 가능, S4 표현·경미한 불편. 실제 심각도 판단은 사람이 한다.
- priority: unset / P0 / P1 / P2 / P3. 긴급 / 높음 / 보통 / 낮음. 심각도에서 자동 확정하지 않는다.
- assignee: 같은 팀의 Owner 또는 Member, 없을 수 있음. Viewer는 작업 담당자로 새 지정하지 않는다.
- fix_note / target_build: Verify 진입 시 필수. 최대 길이는 각각 4,000자 / 120자다. Inbox에서는 선택 입력이다.
- version: 서버에서 증가시키는 정수. UI에 일반적으로 노출할 필요는 없다.

제목만으로 Inbox에 등록할 수 있다. 본문·메모·대상 빌드는 빈 문자열, reproduction은 unknown, severity/priority는 unset, assignee_id는 null이 기본값이다. 아래 표의 상태 이동과 현재 상태의 필수 조건을 유지하는 편집을 허용한다. Done의 일반 필드 편집은 재오픈 전 잠근다.

모든 문자열은 trim 후 빈 값 여부를 검사한다. ECMAScript `String.trim()`과 동일한 공백 집합을 FE/DB에서 제거하고, Unicode 코드 포인트 수로 각 최대 길이를 검사한다(JS `Array.from`, PostgreSQL `char_length`). 단일 한글·이모지는 1자이며 결합 문자/ZWJ 이모지 묶음은 여러 코드 포인트일 수 있다. 재현 단계·기대 결과·실제 결과·환경 중 비어 있지 않은 항목 수를 0~4로 표시하며, 입력 충족 수를 신뢰도나 재현 성공률로 표현하지 않는다.

## 상태 전환

화면 이름과 DB enum: **접수** inbox · **진행 대기** ready · **수정 중** in_progress · **재검증** verify · **완료** done. 아래 표의 영어 이름은 같은 상태를 가리킨다. 한국어 문구 변경은 DB 규칙을 바꾸지 않는다.

| 현재 | 다음 | 조건 |
|---|---|---|
| Inbox | Ready | 재현 필드 4개 충족, reproduction=reproduced 또는 intermittent, 간헐 조건 충족, severity·priority 설정 |
| Ready | Inbox | 사유 메모 |
| Ready | In Progress | 유효한 담당자 지정, Ready 조건 유지 |
| In Progress | Ready | 사유 메모, Ready 조건 유지 |
| In Progress | Verify | 수정 메모·확인할 앱 버전, Ready 조건·유효 담당자 유지 |
| Verify | Done | 현행 이슈 version을 기준으로 재검증 통과 기록 저장과 상태 이동을 같은 명령으로 실행 |
| Verify | In Progress | 재검증 실패 기록과 실패 메모를 같은 명령으로 저장 |
| Done | Inbox | 재오픈 사유, 과거 검증 기록 유지 |

그 외 이동은 MVP에서 거부한다. 같은 상태로 이동은 UI에서 no-op. 드래그로 양식이 필요한 상태를 선택하면 입력 다이얼로그를 먼저 열고, 제출했을 때만 낙관적 이동을 시작한다. 취소하면 이동하지 않는다.

같은 상태의 드롭은 no-op이며 RPC의 같은 상태 요청은 효과 없이 거부한다. 사유/검증 입력 다이얼로그를 제출한 뒤에만 임시 이동과 저장 중 표시를 시작한다. 이동/재오픈 사유는 trim 후 1~4,000자다. 같은 이슈의 편집/이동은 한 요청만 허용하고 다른 카드는 조작할 수 있다. 명확한 거부는 그 요청의 임시 이동만 제거하고, 10초 타임아웃·응답 유실은 결과 확인 중으로 표시한다. 같은 요청으로 명시적 재확인을 제공하며 새로고침/팀 이탈 후 미확정 요청 복원은 아직 지원하지 않는다.

Ready 이후 필드 편집도 현재 상태의 필수 조건을 깨뜨릴 수 없다. 먼저 허용된 되돌림 경로를 사용하도록 안내한다. Done의 재현 정보·수정 내용은 잠그고 재오픈 후 수정한다. 댓글은 계속 작성할 수 있다. 담당자를 Viewer로 강등하면 기존 이슈에 “담당자 재지정 필요”를 표시하고 이후 작업 전환에서 검사한다.

재검증 기록: result(pass/fail), tested_build, tested_environment, note, actor, timestamp, issue_version_before. 통과·실패 모두 버전과 환경 필수. fail은 이유 메모 필수. 행위자는 현재 로그인 사용자이며 클라이언트가 임의 지정할 수 없다. 검증은 동일인이 해도 허용하며 독립 검증을 강제하는 제품이라고 소개하지 않는다.

tested_build는 1~120자, tested_environment는 1~4,000자, note는 최대 4,000자로 정한다. pass 메모는 선택, fail 메모는 공백 제거 후 필수다. 앱 버전은 target_build를 초기값으로 보여주되 실제로 검증한 버전을 입력한다. result·actor·issue_version_before·시각은 DB가 결정하며 과거 검증을 수정/삭제하거나 새 version의 통과로 재사용하지 않는다.

## 권한

동시 편집은 이슈 전체의 version을 기준으로 한다. 서로 다른 필드를 수정해도 같은 version의 요청은 한 건만 성공한다. 원격 변경은 서버 목록을 갱신하지만 열린 폼의 초안과 기준 version을 자동으로 바꾸지 않는다. 충돌하면 최신 값 보기·내 입력 복사·최신 값으로 다시 편집을 제공한다. 마지막 동작은 폼을 최신 서버 값으로 교체하며, 사용자가 다시 편집하고 저장해야 새 요청을 보낸다. 자동 병합·무조건 재전송은 하지 않는다. 상세 닫기·팀 이탈·로그아웃·새로고침 후 초안 복원은 미지원이다.

| 동작 | Owner | Member | Viewer | 외부 사용자 |
|---|---|---|---|---|
| 소속 팀 이슈/댓글/활동 조회 | 허용 | 허용 | 허용 | 거부 |
| 이슈 생성·편집·전환·검증·댓글 | 허용 | 허용 | 거부 | 거부 |
| 내 알림 조회·읽음 | 허용 | 허용 | 허용 | 본인 팀 소속 아니면 거부 |
| 초대 생성·Member/Viewer 역할 변경 | 허용 | 거부 | 거부 | 거부 |
| 타 팀 데이터 접근 | 거부 | 거부 | 거부 | 거부 |

워크스페이스 생성자는 Owner. MVP에서는 Owner 이전·삭제·자가 강등을 지원하지 않는다. 초대는 24시간 만료, 1회 사용, Member 역할만 생성한다. DB에 원문 토큰을 저장하지 않고 해시로 조회한다. 로그인한 사용자가 수락해야 한다. 같은 링크 동시 수락은 한 건만 성공한다.

## 부가 기능의 경계

- 컬럼은 고정 5개. 드래그는 상태 변경이며 열 내부 순서는 정렬 기준이 결정한다.
- 검색은 제목·이슈키의 대소문자 구분 없는 부분 일치. q는 trim/NFC 후 최대 120 코드 포인트다. severity/priority/assignee는 AND 필터다. updated는 수정 시각 내림차순→id 오름차순, priority는 P0→P3→unset→updated→id다. 기본값은 전체/updated이며 주소에서 생략한다. unset은 분류 미설정, assignee=none은 담당자 미지정이다.
- 선택 팀·검색·필터·정렬·상세는 URL로 표현한다. 상세는 필터 밖이어도 같은 팀의 전체 Query에서 조회한다. 필터/검색은 replace, 상세 열기/닫기는 push하며 직접 진입한 상세 닫기도 앱 안에 머문다. 한글 조합 종료 후 300ms 디바운스를 적용한다.
- 잘못된 enum/UUID는 기본값으로 정규화한다. 형식이 맞는 타팀/없는 이슈는 동일 접근 불가 안내, 비회원 팀은 접근 거부, 확인되지 않는 담당자는 일반 안내와 0건이다. URL은 권한을 부여하지 않으며 타팀 프로필을 조회하지 않는다.
- 댓글은 trim 후 일반 텍스트 1~4,000 코드 포인트. MVP에서 수정·삭제 없음. 멘션은 팀 멤버 선택 UI, 중복 제거 후 한 댓글 최대 8명, user id로 저장. 댓글은 이슈 본문 version/수정 시각을 바꾸지 않으며 Done에서도 작성 가능하다.
- 알림은 댓글 멘션만. 이메일·푸시·전체팀 멘션 없음. 자기 알림 제외, 중복 수신자 제거.
- 별도 증거 URL 필드·자동 링크·파일 업로드·서버 링크 미리보기는 없다. URL을 댓글에 입력해도 일반 텍스트로 표시한다.
- 이슈 하드 삭제·중복 통합·취소 상태·자유 상태 편집은 후속 범위.
- `/demo` 신규 읽기 전용 화면은 D10 기능 동결로 후속 범위다. D13은 기존 합성 계정의 실제 앱을 시연하며 샘플임을 명시한다.

## 제품 성공 가설

사용자가 별도 설명 없이 부족한 재현 정보를 알아보고, 수정 완료와 검증 완료의 차이를 이해한다. 외부 사용자 관찰은 NOT_RUN이다. 현재는 합성 데이터의 자기 검증만 있으며 이 가설의 충족을 주장하지 않는다.
