# 실제 시연과 캡처 가이드

상태: 전체 시연 전. D10까지 구현한 실제 앱으로 D13에 실행한다. 신규 기능 동결에 따라 /demo 신규 화면은 후속 범위다.

## 준비

- 로컬 또는 검증된 hosted 개발 환경, 합성 이슈 약 12개.
- 서로 다른 계정 A(Member), B(Member), C(Viewer). 별도 브라우저 프로필/Playwright context 사용.
- title만 있는 Inbox 이슈, Ready 조건 충족 이슈, In Progress 이슈, Verify 이슈를 준비한다.
- 개발 전용 장애 주입 방법은 TEST_REPORT에 기록하고 public production에서는 제거한다.
- 실제 이메일·토큰·비밀 값은 화면에 나오지 않게 한다. 계정 이름은 합성 표시 이름을 사용한다.

## 3~4분 시연 순서

| 시간 | 실제 행동 | 관찰 포인트 |
|---|---|---|
| 0:00~0:25 | 보드·재현 정보 부족 카드 열기 | “무엇을 보완해야 하는지”가 보임 |
| 0:25~0:55 | 정보 보완→Ready→담당자 지정 | 버그 전용 상태 조건 |
| 0:55~1:25 | A에서 이동, B 화면에서 반영 | 별도 사용자 실제 협업 |
| 1:25~2:00 | A/B가 같은 버전을 편집해 충돌 | 성공 1건·초안 보존·최신 값 확인 |
| 2:00~2:30 | 한 이동 실패, 다른 카드 성공 | 해당 이동만 취소·다른 변경 유지 |
| 2:30~3:00 | A 단절→B 변경→A 복귀 | 연결 안내·최신 조회·초안 보존 |
| 3:00~3:30 | Verify의 재검증 통과→Done | 수정과 검증이 구분됨 |
| 3:30~4:00 | Viewer 화면, URL 복원 또는 테스트 결과 | 권한 UX·검증 근거 |

실패를 일부러 주입한 장면은 “개발 환경에서 저장 실패 주입”이라고 표시한다. 잘라 붙인 화면을 실제 동시 협업처럼 연출하지 않는다.

## 최소 캡처 6개

1. 대표 보드: 카드 제목·상태·분류·재현 정보 충족 수.
2. 재현 정보 누락과 Ready 조건 안내.
3. 수정·재검증 폼과 완료 기록.
4. 충돌 화면: 최신 값과 내 초안 보존.
5. 연결 문제와 복구 상태.
6. 실제 테스트 결과: 실행 환경·커밋 포함, 비밀 값 제거.

작은 캡처는 docs/assets에 넣고 대용량 영상/trace는 적절한 외부 영상·Release 자산으로 연결한다. 가상의 URL이나 실행하지 않은 테스트 스크린샷을 만들지 않는다.

## 읽기 전용 샘플

`/demo` 신규 화면은 D10 기능 동결로 후속 범위다. 이번 시연은 기존 합성 계정의 실제 DB 앱으로 진행하고 합성 데이터임을 표시한다. 공유 Owner 자격 증명을 README에 공개하지 않는다.
